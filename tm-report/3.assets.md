# The Entry/Exit points of the AppShield Software Tool

As part of the threat modeling process, we start by decomposing the application with the third step being the finding and identification of the assets.

Below is the assets table with their id and description as examplified in [OWASP Thread Modeling Process](https://community.owasp.org/Threat_Modeling_Process), the ids in bold are the ones identified by AI (Claude):

## Assets

| ID | Name | Description | Trust Levels |
| --- | --- | --- | --- |
| **1** | **Monitored resources** | **Assets relating to the machines AppShield inspects.** | |
| **1.1** | Integrity of the monitored files and registry keys | The files and registry keys on each host are what the whole system exists to protect. AppShield does not own them, but its entire purpose is to detect unauthorised changes to them. | Any user or process able to write to the scanned filesystem or registry; Host service account |
| 1.2 | Ability to read any file or registry key on a host | The host service runs privileged so it can read resources it does not own, including their ACLs. Whoever controls that process inherits near total read access to the server. | Host service account; Local administrator on the host machine |
| **1.3** | Description of a host's contents and permissions | The collected inventory of filenames, sizes, timestamps, hashes, ACLs and registry data maps out a server in detail, which is valuable reconnaissance for an attacker planning a further intrusion. | Anonymous network user; Console process; Console operator |
| **2** | **Admin console data** | **Assets stored locally by the console.** | |
| 2.1 | Trusted baseline of past resource information | The stored record of previous scans is the reference every comparison is made against. If it is altered to match a compromised state, AppShield reports nothing wrong; if it is destroyed, no comparison is possible at all. | Console process; Console administrator; Any local process able to write the file |
| 2.2 | Console user accounts and credentials | The stored users and credentials control who may operate the console and connect to hosts. | Console process; Console administrator |
| 2.3 | Console configuration and preferences | Stored settings including which hosts are monitored and what is scanned. Altering them narrows the scan silently, so resources stop being checked without anyone being told. | Console process; Console administrator |
| **3** | **Channel credentials** | **Assets protecting the console to host connection. The specification does not state that this channel is authenticated or encrypted, so these are recorded as assets under that assumption.** | |
| 3.1 | Credentials or keys authenticating the console to a host | Whatever proves to a host that the caller is a legitimate console. Possession of it allows an attacker to query any host directly. | Console process; Host service account |
| 3.2 | Credentials or keys authenticating a host to the console | Whatever proves to the console that it is talking to the intended host. Possession of it allows an attacker to impersonate a host and feed the console fabricated data. | Console process; Host service account |
| **4** | **System capabilities** | **Assets relating to what an attacker can do rather than read.** | |
| 4.1 | Ability to make the console report no changes | The outcome an attacker on a monitored server most wants, reachable by tampering with the baseline, the host responses, the scan scope or the hashes. It defeats the tool without disabling it, so nothing looks wrong. | Console administrator; Compromised or spoofed host; Any local process able to write the baseline |
| **4.2** | Availability of the integrity checking service | If the host service is stopped or the console cannot reach it, monitoring stops. An attacker gains a window in which changes go unrecorded. | Local administrator on the host machine; Anyone able to disrupt the network segment |
| 4.3 | Ability to execute code as the host service account | Code execution inside the privileged host process, obtained for instance by exploiting the parsing of network requests or of data read from a compromised disk. This is a stronger position than 1.2, since it includes writing as well as reading. | Host service account; Local administrator on the host machine |
| 4.4 | Ability to operate the admin console | Console access allows an operator to query every monitored host, read the baseline and accept new baselines, so it is a single point from which the entire monitored estate is reachable. | Console operator; Console administrator |
| 4.5 | Trustworthiness of the offline boot media | The media carries the code that runs when a machine is already assumed compromised. If its contents are altered, the last resort verification is itself untrustworthy. | Physically present operator; Whoever produced or last held the media |
| 4.6 | Integrity of the reported findings | The comparison results shown to the operator and written to the logs are what any response decision is based on. Suppressed or falsified findings mislead the people acting on them. | Console operator; Console administrator; Monitoring or SIEM operators |
