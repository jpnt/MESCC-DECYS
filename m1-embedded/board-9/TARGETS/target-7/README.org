** How targets 5 and 6 combined to let me connect
The C&C login is two-factor: a static password AND a rotating one-time password.

- [[../target-5][Target 5]] recovered the static *C&C password*
  (=cncgij...hzzaj=, by RSA-decrypting the signature to an MD5 hash and
  reversing it with a rainbow table). This gets past the password prompt but
  stalls at the OTP challenge.
- [[../target-6][Target 6]] recovered the *OTP generator*
  (=x_{n+1} = (3693 * x_n) mod 4096=), so every "one-time" password is
  predictable from a single observed value.

Combined: authenticate with the target-5 password to reach the OTP prompt, send
one guess to learn the board's current expected value, then submit the
generator's next output. In the transcript the guess =1= revealed the board was
expecting =3424=, so the next OTP is =(3693 * 3424) mod 4096 = 480=; submitting
=480= was accepted and the board returned the final secret.

** Note on per-boot seeding
The OTP seed is randomised each boot, so the first expected value cannot be
known in advance. =connect.py= therefore probes once and resyncs off the
revealed value; the fixed multiplier/modulus make every subsequent OTP correct.
