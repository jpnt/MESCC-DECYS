* Q: How did targets 5 and 6 combine to let you connect?
The C&C login is two-factor: a static password AND a rotating OTP.

- [[../target-5][Target 5]] recovered the static C&C password (gets past the password prompt,
  stalls at the OTP challenge).
- [[../target-6][Target 6]] recovered the OTP generator (x_{n+1} = (3693 * x_n) mod 4096), so
  every "one-time" password is predictable from a single observed value.

Combined: authenticate with the target-5 password, send one guess to learn the
board's current expected value, then submit the generator's next output. The
guess 1 revealed 3424, so the next OTP is (3693 * 3424) mod 4096 = 480; that was
accepted and the board returned the final secret.

* Note on per-boot seeding
The OTP seed is randomised each boot, so the first expected value cannot be
known in advance. connect.py probes once and resyncs off the revealed value; the
fixed multiplier/modulus make every subsequent OTP correct.
