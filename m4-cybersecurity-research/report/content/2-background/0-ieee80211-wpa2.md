## The protocol this report attacks

IEEE 802.11 carries frames unencrypted unless a key is installed. WPA2
(standardised as IEEE 802.11i) establishes those keys with a four-party
exchange called the 4-way handshake, part of the RSNA state machine:

1. The authenticator (AP) sends an ANonce.
2. The supplicant (client) replies with an SNonce; both sides can now
 derive the **PTK** (pairwise transient key) from the PMK, both
 nonces and both MACs.
3. The AP sends EAPOL-Key frame 3 of 4, carrying its **Key-Data**
 (the GTK) and, in the **Key-Info** field, the **Install** bit:
 *"install the PTK into your now unicast-keyed hardware now."*
4. The supplicant sends frame 4 of 4; the AP installs its receive key.

The four message roles, field by field (EAPOL-Key, from the paper's
Table 1 and the state machine in Figure 3 [@krack]):

| Msg | Direction | Carries | Effect on the client |
|---|---|---|---|
| 1/4 | AP to client | ANonce | start PTK derivation |
| 2/4 | client to AP | SNonce | complete PTK inputs |
| 3/4 | AP to client | KCK-MIC, **Install bit**, GTK + RSC in Key-Data | install PTK (reset TX PN when Install set), send 4/4 |
| 4/4 | client to AP | MIC over 3/4 context | AP installs; port authorized |
