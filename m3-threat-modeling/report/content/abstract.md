AppShield checks whether the files and registry keys of Windows servers still match a trusted record of how they looked before. A host component collects the data on each server and an administrative console compares it with the stored baseline. The same tool can also be booted from CD or USB to examine a machine that is already believed to be compromised.

This report models the threats to AppShield following the OWASP threat modeling process. The application is decomposed into external dependencies, entry and exit points, assets and trust levels, and drawn as data flow diagrams at three levels of detail for both the normal network mode and the bootable mode. The diagrams are written as pytm models, which also proposed candidate threats that we triaged by hand. Threats were identified with STRIDE per element, ranked with DREAD and an OWASP style qualitative model, and answered with eleven countermeasure packages.

Fifty-seven threats were found. The most serious ones come from three gaps in the design as described: the channel between console and host is neither authenticated nor encrypted, the baseline and configuration are ordinary files that the console does not protect, and console access rests on a password login with no stated limits or roles. The bootable mode removes the network threats but moves trust onto the boot media, the firmware and the drive that carries results back. After the proposed countermeasures, twenty threats are fully mitigated, thirty-six are reduced, and one, hardware that lies below the trusted environment, remains outside what AppShield can address.
